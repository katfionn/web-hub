产品与生态

6 项▾
术语释义出处
DeepSeek Harness模型之外那一整套工程系统：提示词、工具调用、文件系统、沙箱、记忆、上下文管理、约束机制、反馈回路、钩子/中间件、编排逻辑；CLI 包名 @deepseek-ai/dsh，启动命令 npx @deepseek-ai/dsh web。P01·P37
CordisHarness 的插件内核框架（与 Koishi 生态同源）：提供服务注册/注入、事件追加与派发、生命周期钩子三大原语；Harness 所有"一切皆插件"的能力都建立在它之上。ASR 常误识为"CorelX/扣的/科迪斯"。P01·P04
一切皆插件DeepSeek Harness 官网 slogan：模型、工具、技能、会话、沙箱、存储、循环、调度、UI 等所有 Agent 能力均由插件组合而成，可自由替换与灵活重组；默认 159 个插件（P02 帧实证）。P01·P02
四种 Agent 预设标准 standard（功能完整）、PTC ptc（标准全部 + Code Mode SDK 单步多工具编排）、极简 minimal（持久 bash + str_replace_editor）、创造 create（标准全部 + 运行时检查 + 插件实验 + preset 创作指导）。"预设 = 一个会话里 Agent 所运行的插件组装"。P02
MIT 开源DeepSeek Harness 采用 MIT 协议开源，约束的是 Harness 框架层而非模型权重；讲者称"底座属于所有人"。P43·P44
新二八原则P46 观点：AI 把 80% 很快做完，剩下的 20% 是"能跑→好用"的落地活、成本指数上升且必须由人做；Harness 的本质就是让这 20% 做得更快、更高效。80 分半天可得，80→90 约 7 天，90→95 约 30 天，95→98/99 约 3 个月。P46

内核机制

10 项▾
术语释义出处
session 四事件session/created（创建，scope 过滤）、session/disposed（销毁/离开 store）、session/event（追加后广播，fire-and-forget）、session/flush（持久化检查点，awaited parallel durability checkpoint）。全部在内存中发生，flush ≠ 持久化。P04
waterfallCordis 的环绕事件模式 @mode waterfall，洋葱模型，每个监听器可 allow/deny/ask 或 accept/replace/enrich/block。tools 三层、llm/stream 都用它。P05·P07
tools 三层拦截tools/pre-execute（PreToolDecision：allow/deny/ask）→ tools/execute（ToolDispatchExecution）→ tools/post-execute（PostToolDecision：accept/replace/enrich/block）。三者都是 @mode waterfall，讲者拿 Spring AOP 类比。P05
Agent Loop 主循环turn/step 双粒度：入口 → 加载 → 日志/存储 → 输入 → prompt + 工具 → agent-loop → LLM → END，END 是状态值而非独立步骤。七步循环详见 P06/P08。P06·P08
LlmAdapterexport abstract class LlmAdapter（describe / stream）+ interface PreparedLlmCall（config / retryPolicy / context / adapterDefaults）+ class LlmRuntime extends Service；stream() → streamWithRegistration() → ctx.waterfall(this, 'llm/stream', options, ...)。换模型不改源码的机制。P07
插件树三层Harness 插件配置的覆盖结构：用户级 → 项目级 → 系统级，从 apps/cli/src/bin.ts 入口进入，逐层叠覆盖。P03
持久化三件套插件列表里名字带 storage / storage-json / 守护线程的三个插件，负责把 flush 之后的检查点真正落盘。P04
FiberStateagent-loop 内的状态机：UNLOADING / DISPOSED / FAILED 属于 INACTIVE_STATES，FactoryOwnership 类跟踪 accepting / teardown / inactive / liveAgents / startupTasks。P06
插件 ≠ 工具插件是"注册了什么能力"，工具是"某次会话实际挂上去、model 能调的"。159 个插件，但一次对话经 prompt 组装后实际可能只有 3 个工具。P02
system-prompt 插件packages/core/system-prompt/src/index.ts，负责把会话级信息（含运行时注入的用户偏好）拼成最终 system prompt。P05

项目实战 · LangChain Deep Agents 层

10 项▾

口径校正

P22–P36 讲的"Harness 架构"落地实现，实际是 LangChain 的 Deep Agents 框架（create_deep_agent）；ASR 中"longch/狼嵌"→ LangChain、"long graph/狼graph"→ LangGraph、"deep agent/DA 框架"→ Deep Agents、"ASYC/ASIC sub agent"→ AsyncSubAgent。

术语释义出处
Deep AgentsLangChain 团队的框架，提供 create_deep_agent API；本项目的底座（非讲者自研）。0.5 后新增 AsyncSubAgent，讲课时已到 0.6.7。P22·P33
LangGraphDeep Agents 的图状态机底座；Command(update={...}) 把 write_todos 产出写进 graph state 独立字段，从而不被摘要、不被裁剪。P18·P33
CompositeBackend组合多个文件后端，按 URL 路径路由：/memories/ → StoreBackend，/persisted-skills/ → StoreBackend，default → SandboxBackendProxy。讲者在 P26 用代码演示。P19·P26
StoreBackend虚拟文件系统后端，可落 MongoDB / Redis / PostgreSQL / 内存；"文件名只是抽象，存哪里无所谓"。P28
SandboxBackendProxy稳定的沙箱句柄 + 热替换：沙箱重建时引用不丢失。P22·P23
OpenSandbox阿里云的隔离沙箱容器服务，本项目默认镜像 sandbox-registry.cn-zhangjiakou.cr.aliyuncs.com/...，PYTHON_VERSION=3.11，cpu=2 / memory=4Gi / timeout=2h，network_policy 默认 deny + egress 白名单 pypi.org / *.github.com。P15·P23
MCP (Model Context Protocol)魔塔社区 MCP 广场发布的 24h 有效期 MCP-Server（URL 形如 AF389...），过期即报错；提供图表可视化能力。P28
write_todosPlanning 工具：内部再调一次推理模型生成清单，再用 LangGraph 的 Command 写进 graph state 独立字段。入参含 context + 流程描述（流程来自 skill 的 md 文件）。P17·P18
task 工具子 Agent 调度工具，由 SubAgentMiddleware 提供，主智能体用它把任务委派给子智能体；子 Agent 间上下文完全隔离。P20·P26
AgentLoaderapi_view/agent_loader.py 单例，负责预计算（MCP 工具 + 图表工具 + YAML 配置）+ 生命周期管理，启动日志可见"已加载子 Agent 配置：procurement-analyst ← procurement_analyst.yaml"。P26·P15

渐进式披露progressive disclosure：启动时只把每个 Skill 的 frontmatter 注入提示词（每条约 200 token），按需激活后才加载全文；节省 token 预算的核心机制。P25
assign_skillSkill 管理工具：把 Skill 目录移动到目标 scope（main/order/procurement…）+ 调 StoreBackend 持久化，使沙箱回收后 Skill 不丢。P24·P25
scopeSkill 的作用域（main/order/procurement/procurement-analysis…），决定哪个子智能体能看见哪些 Skill；子智能体配置文件中的 skills: [/skills/order/] 即按目录发现。P25·P30
执行与存储分离沙箱随时回收，Skill 必须落到 StoreBackend 持久化；这是"沙箱回收带走 Skill"痛点的工程解法。P24
SkillsSyncMiddleware钩子 before_agent + abefore_agent，把本地 skills 增量同步到沙箱容器；与 UserSkillsRestoreMiddleware（沙箱重启后恢复）协作。P25·P32

上下文工程与记忆

9 项▾
术语释义出处
驾驭工程Harness Engineering：2026 年 2 月之后出现的阶段（提示词工程 2022–2024、上下文工程 2025.2 之后）；三者是包含关系。公式 Agent = Model + Harness（LangChain 团队文章，约 126K 阅读量）。P16
上下文工程四流程Input（提示词+工具描述+Skills 元数据+偏好）→ Compression（自动/手动/隔离三层）→ Isolation（多智能体上下文完全隔离）→ Long-term Memory（/memories/{user_id}/preferences.md + StoreBackend）。P26
压缩三机制① 85% 阈值自动摘要（SummarizationMiddleware 保底）；② 手动 compact_conversation 工具（SummarizationToolMiddleware 暴露，Agent 自主决策）；③ 子智能体隔离（天然减小上下文）。P26·P32
preferences.md用户偏好文件：6 字段（图表类型 / 货币 / 语言 / 最近供应商 / 最近查询 / 其他）；文件名只是抽象，真正存的是字符串；不存在则创建，存在则读取；由 ContextInjectionMiddleware 每轮注入、MemoryUpdateMiddleware 每轮写回。P28·P29
checkpointLangGraph 内置持久化机制；主智能体 271/281 行设 checkpoint，用 mongosave（Mongo 版 Saver），URI 形如 mongodb://root:123456@39.100.100.228:27017，库 mongo_test。P28
SUMMARY_MODEL摘要专用模型 deepseek-v4-flash，temperature=0.3，max_tokens=25600，thinking.disabled；节省成本 + 稳定输出。P27
FALLBACK_MODEL备用模型 glm-5.1（智谱 GLM），max_input_tokens=12800 / max_output_tokens=8192，主模型故障时自动切。P27
主动 compact 触发条件写在主智能体 system prompt 中：① 收到子 AI 返回的长篇报告必须调用；② 完成零配件对比分析后；③ 对话超过 6 轮且距上次压缩超过 3 轮。P32
_extract_ai_summary取最后 AI 消息前 300 字符作为摘要输入；MemoryUpdateMiddleware 的辅助函数。P29

中间件与运行时

11 项▾
术语释义出处
中间件 9 + 8用户绑定 9 个（7 自定义 + 2 LangChain 内置 ModelCallLimitMiddleware / ToolCallLimitMiddleware，必须手动绑定才生效）+ 框架自动注入 8 个（create_deep_agent 时自动加）。P32
SandboxHealthMiddleware#1 自定义；钩子 before_agent，每轮 ping 沙箱，失败自动重建。P32
SandboxCircuitBreakerMiddleware#7 自定义；沙箱连续报错 2 次即熔断，与 #1 协作形成双重保险（自愈 + 熔断）。P32
ContextInjectionMiddleware#2 自定义；钩子 before_agent + abefore_agent，注入 user_id / username / 用户偏好到 SystemMessage。P29·P32
MemoryUpdateMiddleware#6 自定义；钩子 after_agent，每次对话后自动写回 /memories/{user_id}/preferences.md，更新 recent_suppliers 与 recent_queries（追加模式）。P29·P32
interrupt()代码级人工介入：调用该函数即触发中断；灵活，可收任意补充信息。例 request_order_info 工具内含。P30
interrupt_on配置级人工介入：YAML 中为特定工具（order_create / order_update）配白名单 allowed_decisions: ["approve","reject"]，克制。讲者自研 DSL，由 loader.py 翻译成 LangGraph 的 interrupt_on 节点配置。P21·P30
SSE 事件流FastAPI StreamingResponse + Python 生成器 yield，media_type="text/event-stream"；chunk_type 分支决定前端渲染成 AI（蓝）/ 工具（黄）/ 中断（横幅）。比 WebSocket 轻量，单向流。P31
AsyncSubAgentDeep Agents 0.5 后新增的预览功能：主智能体调 start_async_task → Agent Protocol Server → 异步子智能体，20–50ms 即返回 task_id，前端每 5 秒轮询 /api/async-tasks/{task_id}。异步 ≠ Python 协程，而是生命周期从主请求里拆解出来。P33·P34
Agent Protocol Server由 Deep Agents 提供，本质是 LangGraph 本地服务（langgraph dev --host 127.0.0.1 --port 2024）；职责 7 条：创建 thread、启动 run、查询状态、保存上下文、取消任务、追加指令、远程 Agent 统一协议。控制链路单向收敛。P33
77 步请求链路飞书文档中的完整请求时序图：从用户输入 → stream_chat_response → get_display_messages → Command(resume=...) → agent.astream → 子 Agent 恢复 / 中断触发 / HITL 审批 / 订单创建 / 消息保存。P31
