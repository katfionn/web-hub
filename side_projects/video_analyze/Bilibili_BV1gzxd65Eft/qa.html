Harness 是什么？

2m06 ▼
一句话回答 Harness 是模型之外那一整套工程系统——模型负责判断，它负责其余一切。
P38

为什么同一个模型在 A 工具好用、在 B 工具就变笨？

2m17 ▼
一句话回答 因为你面对的不是裸模型，而是"模型 + Harness"；模型只保下限，Harness 决定上限。
P39

DeepSeek Harness 是模型还是客户端？

3m58 ▼
一句话回答 两者都不是——它是一套用来构建、运行、扩展 Agent 的开源框架。
P40

核心设计哲学是什么？Cordis 是什么？

2m26 ▼
一句话回答 哲学就五个字"一切皆插件"；Cordis 是只做装载、不承载能力的分层内核，于是系统里没有一个写死的内核。
P41

四种开箱即用模式各自用途？

3m57 ▼

P42

DeepSeek Harness 的透明体现在哪里？

2m12 ▼
一句话回答 模型"能看到的一切"——系统提示词、思维链路、每次工具调用、每次上下文注入——全部写进一份只增不改的会话日志，于是整条执行轨迹逐条可查、可恢复、可分叉。
  • 透明 = 全量留痕 + 只追加，不是给结果摘要：每一步的输入（上下文注入）与动作（工具调用）都落盘，事后不改写。
  • 现场演示：提问"帮我写一个贪吃蛇"，先 think、再深度搜索，思考全过程直接摊开给用户看。
  • 思考里在做方案抉择：桌面版 / Python 命令行版 / HTML 版三条路，最终选 HTML 版（最快），生成单文件代码；完成后自报"已创建 + 怎么玩 + 怎么部署 + 有哪些功能"。
  • 日志衍生三种操作：逐条可查、可恢复、可分叉——从某一步另走一条路线（如改走纯 Python 命令行），也可把分支复制出来继续对话。
  • 定位能力升级：过去只知"结果错了"，现在能指出哪一步、哪个工具、哪段上下文出错。
  • 三个收益可当工程指标用：可调试性、可复现性、信任度。
让这个 Agent 从原来的黑盒子变成了一个玻璃盒子。
P43

DeepSeek 的开源生态策略有什么独特之处？

3m11 ▼
一句话回答 不是"发布后再慢慢建生态"，而是发布前就把需求（卡脖子）、姿态（主动开源）、门槛（低费用）、社区（提前招募 + 全栈接入只认一个标签）四件事铺完。
  • 卡脖子是需求前提：讲者称 Claude Code 及若干国外工具会针对中国用户、或员工中含中国人的海外公司"卡脖子"（未给具体手段）。
  • 开源姿态：国外模型多不开源，或只是"迫于压力"开放一部分；DeepSeek 是主动开源。
  • 费用：生态费用做得很低，"可以放心大胆、大量地用"。
  • 提前铺社区：25–26 年就开始筹备；还没发海报、没有 demo 时，几天内近千位开发者带项目报名，社区戏称"开源 Agent 的春晚"。
  • 公开招募 + 官方样例：8 月初团队负责人在 GitHub 公开招募内测开发者，只需留 GitHub ID 与代表作；随后放出一批内测插件。
  • 接入面全摊开：Skills、MCP、UI 等全栈"来者不拒"；仓库打上 DSH 标签即可运行、并被生态发现。
  • 结果只给定性：GitHub 上"昨天发布的东西"star 涨得"非常恐怖"，未给数字。
他不是说在发布之后慢慢建立生态，他是在发布之前就已经把开放社区的生态给铺开了。
P44

和 Claude Code 对比，商业逻辑有什么不同？

2m14 ▼
一句话回答 Claude Code 证明 Harness 是门年化几十亿美元的产品生意；DeepSeek Harness 证明同一件事可以"光明正大用开源做"——MIT、模型可插拔、免费、靠生态共建增值，核心资产从"产品"换成"生态和框架"。
维度Claude CodeDeepSeek Harness
源码闭源MIT 开源
模型锁 Claude一切皆插件，可换
商业模式订阅收费生态共建 + 能力增值
核心资产产品本身生态和框架
  • 幻灯片首行即给量级："ClaudeCode 证明了 Harness 是一门年化几十亿美元的生意"（口播为"一年几十个亿"，未给出处）。
  • 开源史被点明：Claude Code 当年"出了错误、泄露了一部分源码"，但本质上仍属闭源。
  • MIT 被讲成"底座属于所有人"：约束的是 Harness 这层框架，不是模型权重；"模型可以插拔，不锁定任何一家"。
  • 可插拔是产品级事实：设置里能直接改模型、填自定义接入；默认只在首次安装时推荐 DeepSeek，删掉换别家"没有任何问题"。
P45

为什么说模型在变成水电煤，Harness 成为新主战场？

1m45 ▼
一句话回答 模型（Kimi、智谱、GLM 等）能力与价格双双趋同、退化成水电煤之后，差异化整体上移到模型之外那一层——工具调用、沙箱、记忆、编排、错误恢复、透明性与生态，Harness 于是成了"模型之上的操作系统"。
P46

个人观点：Harness 与新二八原则

3m34 ▼
一句话回答 AI 把 80% 很快做完，剩下的 20% 是"能跑→好用"的落地活、成本指数上升且必须由人做；Harness 的本质就是让这 20% 做得更快、更高效。

新旧二八对照

旧二八：80% 的时间写代码，20% 的时间调试与维护。

新二八：80% 的代码 AI 很快产出，剩下 20% 是把它落地到"好用"——联调、边界、权限、安全、可观测、生态对接。这 20% 的成本指数上升，且必须由人来做决定。

把 10 个回答串成一条线

定义

Harness 是模型之外的一整套工程系统（P37、P39）；同一模型表现不同，因为上限由 Harness 决定（P38）。

机制

一切皆插件 + Cordis 只做装载（P40）；四种预设是四种插件装配（P41）。

价值

透明日志让执行可查、可恢复、可分叉（P42）；这是"玻璃盒子"的工程价值。

商业

开源生态提前铺（P43）；与 Claude Code 相比，资产从产品换成生态（P44）。

趋势

模型水电煤化 → 差异化上移到 Harness（P45）；本质是让落地的那 20% 更快（P46）。
