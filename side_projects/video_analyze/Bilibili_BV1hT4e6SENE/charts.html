图表库：从原片手绘到矢量重建

视频里的图表大多是讲师现场手绘、或夹在幻灯片与 Google Doc 里的示意图。这一页把其中 9 张核心图表全部用 SVG 重绘——比 720p 截图清晰，标注统一，并且完整保留了原片的论证逻辑。每张图都标注了出处时间戳。

图 01三腿凳：评估体系的最小完整结构

P1 课堂里讲师画过的那个"凳子"——P2 答疑时他直接引用："if you remember the diagram I had, like a stool or a chair with three legs（21:00 前）。无论你打开 Braintrust、LangSmith、CrewAI 还是 Agentforce，看到的都是这张凳子的不同皮肤。

腿讲师原话要点落地要点
① 数据集"a place to start creating your test scenarios, AKA dataset… and then it is versioned as you update them"按用途命名与版本管理：regression / unit / security red-team 各自独立演进
② 指标与评委"you define what metrics you will use and what judge you will use"评分可以是平台自带（factuality / security check），也可以自定义 scorer；评委分为人、LLM、混合三类
③ 实验"once you have those three legs… you can set it up as an experiment"实验 = 数据集 × 评委 × 被测对象的组合执行，产出可比较的分数表

图 02Eval 闭环：从 trace 到 ship gate

P2 结尾讲师用一篇博客（“How to write evals for anything”）串起全课程："look into the traces, annotate and find out what are the failures → pick a grader → run → decide ship or not ship → 不过就 tune、再跑、校准"。这是整个课程的主循环，Week 1 只在最左端（看+标），Week 2 补上 grader。

图 03为什么 A/B 测试救不了 LLM 应用

课程平台首页嵌着一支约 19 分钟的入门视频《The Unexpected Journey of AI Deployments》（Instructor 出镜，学员课后自看）。讲师在 P1 开场打开它的预览页演示"去哪找材料"，视频用一张 A/B 实验曲线和一块"满屏退化"的指标表，论证了传统发布方法论在非确定性系统上为何失灵——这是整门课的问题起点。

论点拆解：A/B 测试的三个硬伤——① 需要巨大样本量才有统计力；② LLM 输出非确定性、方差高，均值不告诉你"错在哪类问题上"；③ 只给一个总体的胜负结论，不给"哪个失误让用户流失"的可执行洞察。Evals 的解法恰恰是把"逐类问题"变成可测量的条目。

图 04Trace 解剖：Session → Turn → Span → Tool Call

P2 里讲师反复强调："先看 chat transcript（20/80），再下钻 spans"。这张结构图还原了 Braintrust 界面里那个多轮对话的层级：每个 turn 有 root span 和 LLM span，span 里藏着延迟、token、成本和工具调用链。

图 05工具栈架构：trace 从哪来，到哪去

讲师在黑板上画过这张架构（P2 25:53）：Agent 运行时在内存里产生 logs/traces → 缓存几小时就消失 → 必须一次性接入可观测平台 → UI 用于看结果/标注，SDK 用于自动化跑评测。Braintrust 不是运行时，只是"评估与可观测"的落点。

图 06评估成熟度阶梯：从 playground 到 Ship Gate

P2 里讲师横跨四个产品演示了同一条成长路径。每一级对应不同的工程纪律：随手单测 → 回归批量实验 → CI/CD 与夜间批跑 → 发布门禁。

图 07Grader 光谱：从正则到 LLM Judge

Week 1 的 grader 是代码（正则匹配），Week 2 换成 LLM Judge——但不是"用 LLM 取代一切"，而是随判据的语义复杂度做梯度选择。讲师明确说："the idea is high level code base graders and more model base grader"。

图 08多轮评估：两个层级都要判

学员 Uma 问"一次输入带四个问题该怎么判"，讲师答："You need to do both — each turn level and the final pass and fail, because the final pass/fail is: did the user's issue get solved?"（P2 17:52）。

图 09Evals 团队长什么样（原片视频截图重绘）

P1 开场视频里出现过一张 20+ 人的组织图（Google Doc 截图，原片 10:45），配文是"为每个 GenAI 功能做测试与评估 / 对质量给出诚实估计"。它回答了一个很现实的问题：评估不是一个工具，是一个跨职能建制。
