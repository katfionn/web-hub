C三张清单

① Trace 标注流程

  1. 先读 chat transcript（人话）
  2. 下钻 root span → LLM span → tool calls
  3. 对照业务工作流判 pass / fail，并写理由
  4. 给失败归类（refund / warranty / context / tool…）
  5. 标注失败层级：模型 / 工具 / 会话 / harness
  6. 多轮对话：每轮独立一行 + 会话 ID
  7. 统计问题分布 → 决定下一步修什么

② Span 检查六项

  1. input / output 全文
  2. tokens 数（过少=提示词没进来）
  3. 总耗时 latency
  4. 首 token 时间（体感延迟）
  5. cost
  6. tool 调用链与参数（走了哪条路径）

③ Ship Gate 三要素

  1. 分层的数据集（真实 + 合成 + 红队）
  2. 与人工标注对齐过的评委
  3. 阈值 + 关键场景红线（安全零容忍）

配套：实验跑进 CI/CD；夜间批跑；代码 grader 与 LLM Judge 混合。

④ 判定三原则

  • 站在业务工作流上判（先认证后动数据）
  • 允许标注者差异，但必须写清理由
  • 本阶段目标是"可讨论的一致"，不是绝对正确

G术语与映射（精简版）

概念一句话定义别名（其他平台）
Dataset带期望行为的输入集合，可版本化test set / scenario set
Scorer输出 → 分数 / pass-fail 的函数metric / evaluator / grader
Experiment数据集 × 评委 × 被测对象的一次执行batch test / regression run
Playground单条输入的人机对练台prompt IDE
Trace / Span一次完整执行及其子步骤的记录log / run / observation
Harness驱动被测对象的脚手架环境test harness / eval harness
LLM-as-judge用模型按 rubric 评分model-based grader
Ship gate用评估结果做发布判定release criteria / quality gate
